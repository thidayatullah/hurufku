# 0004 — Phone / Compact Layout

## Context

Phase 1 of the responsive work ([0002_PLAN.md](0002_PLAN.md)) moved tablet/desktop to a canvas-first shell with top overlay islands and a left portrait property panel. That layout does not fit a phone: the letter grid is ~630px wide against a 360px viewport, control sizes are fixed pixels, and the left panel plus bottom islands crowd a narrow screen.

This phase adds a compact layout modeled on the Excalidraw mobile reference: all chrome docks to the bottom, a secondary button row sits above the main toolbar, and inspectors open as popover cards anchored to the tapped secondary button.

User requirements, verbatim:

- "The menu moved the bottom"
- "Added secondary buttons on top of the main toolbar"
- "The secondary button will show the inspector menu when tapped"
- "Use paint bucket icon for the button to open color inspector"
- "Scale everything, nothing will be clipped, everything will be displayed properly based on the screen size (sticker grids, toolbars, text, menu, icon, etc)"
- "In compact mode it's allowed to remove label from an icon and just keep the icon"

Confirmed decisions:

- Secondary row contains: Color (paint bucket), Stroke (type + weight), Text (size + font), Speak, Make sticker, Delete selected.
- Brand stays top-left as an icon-only mark; language becomes a compact flag-only toggle top-right.
- Inspector is a popover card anchored above the tapped secondary button.
- Sticker grid shrinks tiles fluidly so all 10 / 9 / 7 columns always fit.
- Compact breakpoint is `max-width: 640px` or `max-height: 500px`.

The tablet/desktop layout above the breakpoint is unchanged.

## Breakpoint

Compact mode triggers on `max-width: 640px` **or** `max-height: 500px`.

`640px` covers every mainstream phone portrait width (360 Galaxy/Android, 375 iPhone SE, 390 iPhone 13–16, 412 Pixel, 430 Pro Max) with headroom, and stays below the smallest tablet portrait width (744 iPad mini, 810 iPad, 834 iPad Pro 11") so tablets keep the desktop layout.

The `max-height: 500px` condition catches landscape phones (for example 844×390), where the viewport is wide enough to miss a width-only query but far too short for the tall left portrait panel.

- Any new ligature renders as literal text until it is added to this list.

## Algorithms

### Compact chrome layout

1. `main.board-wrap` remains the full-viewport positioning root; `BoardCanvas` still receives the full measured width and height, so the board stays full-bleed behind the chrome.
2. In compact mode, the bottom dock is anchored to the bottom edge, horizontally centered, and padded with `env(safe-area-inset-bottom)`. `viewport-fit=cover` is already set in `index.html`, so this reclaims the iOS home-indicator area.
3. Dock children stack bottom-up: the main tool row on the bottom, the secondary row directly above it.
4. The compact top row holds the icon-only brand mark and the zoom cluster on the left and the flag-only language toggle on the right.
5. `.zoom-island` and `.action-island` stop rendering as independent bottom islands in compact mode, since Make sticker moves into the secondary row and zoom joins the top-left cluster.

### Inspector popover

1. Tapping a secondary button sets `activeInspector` to that button's key; tapping the same button again clears it.
2. Only one inspector is open at a time.
3. The popover renders above the dock, anchored horizontally to its trigger and clamped so it never extends past the viewport edge.
4. Popover contents come from the shared property sections:
   - Color — swatch grid, wired to `chooseInkStyle` for Pencil or to `chooseStyle` / `chooseScribbleStyle` for a selected item.
   - Stroke — brush type and weight.
   - Text — letter size and font, shown only when the selection is a letter.
5. The popover dismisses on: tool change, tap outside, `Escape`, or the selection becoming empty.
6. `activeInspector` is ignored above the breakpoint, where the left portrait panel continues to render inline.

### Fluid sticker grid

1. `.letter-island` becomes a 10-column grid rather than three independent flex rows.
2. Row 1 places the 10 glyphs of `ABCDEFGHIJ`.
3. Row 2 places the caps-lock button plus the 9 glyphs of `KLMNOPQRS`, filling the same 10 cells.
4. Row 3 places the 7 glyphs of `TUVWXYZ`, centered within the 10-column track.
5. Tiles size themselves with `width: 100%` and `aspect-ratio: 1`, with a clamped font size, so all 26 letters fit at 360px with no scrolling and no clipping.

### Placement inset

1. `addGridSticker` currently derives `visible.bottom` from the full canvas height, so a wrapped row can land underneath the dock.
2. Subtract the docked chrome height from `visible.bottom` before calling `placeStickerFromGrid`.
3. `nextRowPoint` in `src/board/board.ts` already clamps against `visible.bottom`, so the corrected rect makes wrapping land above the dock without further reducer changes.

## Phases

### Phase 1 — Fluid scale foundation

`src/index.css` only: fluid tokens, repointing fixed control sizes, and the `.control-label` class. No layout moves. Everything else depends on this.

### Phase 2A — Compact chrome

Bottom dock, secondary row, compact top row, and the removal of the separate zoom and action islands in compact mode.

### Phase 2B — Inspector popovers

`activeInspector` state, shared property-section extraction, popover rendering and dismissal, and the `index.html` icon subset additions.

### Phase 3 — Grid and placement

Grid-based `.letter-island` and the `addGridSticker` bottom inset.

### Phase 4 — Docs

`docs/DESIGN.md` compact layout, icon-only rule, and icon table updates.
